# Polyglot Riff Studio — Workspace Rules & SSOT Lineage

1. **Read `CODEBASE_LINEAGE_AND_MAP.md` First**:
   - Before modifying data, schemas, or frontend views, consult `CODEBASE_LINEAGE_AND_MAP.md` for the exact file responsibilities across all 6 HTML studio views and the 4-layer Python backend.
2. **Never Hand-Edit `db/*.db.json` Shards**:
   - The 6 JSON files in `db/` (`cz_ova.db.json`, `at_vie.db.json`, `ru_ala.db.json`, `en_yyc.db.json`, `es_sot.db.json`, `polyglot_fabric.db.json`) are derived artifacts generated by `backend/services/sync_service.py`.
   - Always edit the canonical seed files (`backend/seed/corpus_data.py`, `backend/seed/arena_decks_8.py`, `backend/seed/ib_vocab_data.py`) and run `.\.venv\Scripts\python.exe -m backend.cli seed --no-embed` (or `export-shards`).
3. **Preserve Cross-Tab Culture Synchronization (`PolyglotSyncBus`)**:
   - All 6 HTML studio apps load `polyglot_api_client.js` and synchronize active culture (`CZ_OVA`, `AT_VIE`, `RU_ALA`, `EN_YYC`, `ES_SOT`) via `window.PolyglotSyncBus`. Use `PolyglotSyncBus.normalizeCulture()` when translating between uppercase register IDs (`CZ_OVA`), lowercase keys (`cz_ova`), and ISO codes (`cs`).
4. **Verify 9-Point Audit Before Publishing**:
   - Always run `.\.venv\Scripts\python.exe -m backend.cli audit` and verify `"ok": true` before running `.\publish_github_pages.ps1`.
